## 1. Sentinel-LLM — LoRA Fine-Tuning for Cybersecurity Threat Intelligence

- Re-ran the project on **real public benchmarks** under a strict protocol (all model selection on validation; each selected system evaluated on test once): MITRE ATT&CK tactic classification from the official CTI STIX bundle (706 techniques → 15 tactics, first-tactic single-label, stratified split) and CVE severity prediction from the NVD (4,400 CVEs, **temporal split** — train 2020–21 / validation 2023 / test 2024 — with CVE-ID and year tokens stripped from features). The best verified system — TF-IDF word 1–2-grams + linear SVM — reached **79.46% accuracy / 0.7788 macro F1 on ATT&CK test**, level on macro F1 with the published bar (81.95% / 0.7795, different corpus and protocol), and **55.70% / 0.5444 on CVE test**, below the literature ceiling of ~70% set at ~36k-CVE scale.*
- Reported the Round 1 lesson plainly: the from-scratch LoRA model that scored 100% on the project's synthetic data reached only **49.11% (ATT&CK) / 48.90% (CVE)** on real data, losing to full fine-tuning and to TF-IDF; Round 2 therefore compared three pre-registered families (TF-IDF, hybrid, neural) — and caught its own earlier error, when the strongest Round 1 TF-IDF variant (inner-validation macro F1 0.634) proved to be a same-era split artifact (0.517 on the true 2023 validation split), while the small neural model's features added nothing over tuned TF-IDF.*
- Implemented LoRA from scratch in PyTorch (low-rank adapters, zero-initialised B matrix, α/r scaling, dropout) with a 4-configuration sweep and a full fine-tuning baseline; on real data the LoRA-vs-full-FT comparison survives as an efficiency result — LoRA within ~6–9 points of full fine-tuning at under 2% of trainable parameters — while the synthetic sweep's 100% headline does not transfer and is retained only as a pipeline proof.*
- Authored a packaged PEFT/QLoRA script (4-bit NF4) to fine-tune Qwen2.5-0.5B-Instruct on GPU as the documented next step — **written and ready to run, not yet run**; no accuracy is claimed for it.*

## 2. DenseHAR — Transition-Aware Dense Human Activity Recognition

- Built a dense (per-timestep) activity-segmentation network in PyTorch extending the InceptionKAN encoder — multi-scale 1D convolutions (k = 1, 3, 5, 11), SE attention and a dilated temporal stack — at 68,898 parameters, and evaluated it on **real HAPT data** under a strict subject-disjoint protocol (train 21 / validation 4 / test 5 unseen subjects; normalisation statistics from train subjects only; all model selection on validation).*
- Final system — physics-respecting augmentation, 12-class transition supervision, a 3-seed probability ensemble and validation-tuned post-processing — reached **90.38% per-timestep accuracy and 0.9398 macro F1** on the 5 unseen test subjects vs **78.91% / 0.7258** for a window-128 baseline under the identical protocol; transition-window accuracy 0.6093 vs 0.4787 and 87.44% accuracy on the transition-class timesteps themselves.*
- Ran a two-phase, validation-screened improvement programme (22 logged experiments): the phase-1 configuration tied the baseline on real data (78.86% vs 78.91%), after which screening identified physics augmentation as the largest lever (validation F1 0.9189 → 0.9584) — and produced reportable negative results: median-frequency class weights hurt, and boundary-weighted cross-entropy was a null result vs plain cross-entropy.*
- Reported the full MS-TCN-standard segmental suite (boundary F1 0.4087; segmental F1@10/25/50 = 0.836/0.822/0.788; edit score 84.88 vs baseline 75.52) and per-class analysis: dynamic classes solved on unseen subjects (walking and walking-upstairs F1 1.000, downstairs 0.994) with sitting vs standing (0.853 / 0.815) the remaining hard pair. An earlier synthetic-data run (95.35%) is retained only as a preliminary pipeline proof.*

## 3. AgentForge-RAG — Agentic RAG with Hybrid Retrieval, Guardrails & Evaluation

- Re-ran retrieval on a **real public benchmark — SciFact via BEIR** (full 5,183-abstract corpus, document-level title+abstract chunks, 300 test queries; all tuning on the 809 train/dev queries only). The final pipeline — BM25 (k1 = 1.0, b = 0.5) + TF-IDF with title-cosine boost (β = 0.5), reciprocal-rank fusion (w = 0.3), no reranker — scored **nDCG@10 0.6466, Recall@5 0.7059 and MRR@10 0.6090** on its single test evaluation.*
- Published the ladder honestly: naive TF-IDF 0.5769 → hybrid TF-IDF+BM25 0.6269 → hybrid + rerank 0.6429 nDCG@10, so the final system beats its best baseline rung by only +0.0037 and remains **below the published BEIR BM25 bar of 0.665** — a documented plateau for this purely lexical stack. The internal 100% Recall@5 (28 questions over a 14-document self-authored corpus) is retained only as a pipeline sanity check.*
- Screened 44 improvement attempts on dev queries only and logged the negatives: **RM3 pseudo-relevance feedback hurt (0.6085–0.6259) and was rejected**, as were BM25F field weighting and Porter stemming (−0.151); diagnosed that the default fusion weight dilutes BM25 (BM25 alone outscored the default hybrid on dev) and that the project's cybersecurity query-expansion lexicon is inert on SciFact (0 of 250 dev queries changed).*
- Built the system zero-dependency in Python/NumPy — Router, Retriever and Verifier agents, hybrid TF-IDF + BM25 implemented from scratch, deterministic reranker, evaluation harness plus 25 passing tests — with trust guardrails verified on the internal eval (groundedness 28/28, abstention on unanswerable questions 5/5, prompt-injection blocks 5/5, PII redaction on inputs and outputs); SciFact does not benchmark those behaviours, so they remain internal-eval-only claims.*

## 4. DiffusionForge — Diffusion Models From Scratch (DDPM + DDIM + Classifier-Free Guidance)

- Re-ran the from-scratch diffusion pipeline on **real MNIST** (SHA-256-verified download; 60,000 train / 10,000 test) downscaled 28×28 → **16×16** so the existing U-Net applies unchanged — stated in every result; the numbers are not comparable to 28×28 FID literature and **no FID is claimed**. The fidelity classifier first had to pass an evaluator gate: **98.13% accuracy on the held-out real test split**.*
- Final system (validation-selected: +12 further epochs, no augmentation, 24 epochs total) reached **DDPM-300 class fidelity of 100.0% (70/70 samples)** and **DDIM-50 fidelity of 84.29%** at guidance w = 1.5, with test noise-MSE 0.0576 and sample diversity close to real data (pairwise L2 9.364 / 9.525 vs 8.977); a memorisation check came back clean — generated samples sit at normal inter-image distances from the training set (0% below L2 1.0, vs 5.6% for real test images) — so the 100% is novel samples, not copies.*
- Implemented the full pipeline from scratch in PyTorch — linear/cosine noise schedules, closed-form forward noising, a time- and class-conditioned U-Net (180,049 parameters on the real run) and classifier-free guidance training (10% label dropout) — with no library diffusion code; guidance was re-swept on validation only (w = 1.5 selected), and the ~16-point DDIM-vs-DDPM fidelity gap is reported as the project's open problem.*
- Logged the screened-out levers as negative results: EMA decay 0.999 collapsed the validation fidelity proxy to 11% at this step count, and ±2px roll-augmentation runs scored 55–58% on the proxy and were dropped; all selection used the validation fidelity proxy, with the test set evaluated exactly twice (baseline config once, final config once).*

## 5. FedGuard — Federated Learning with Differential Privacy

- Re-ran the federated engine on **real MNIST downscaled to 16×16** (256-input MLP, 21,258 parameters; 10 clients; a stratified 5,000-image validation split carved from train drove all selection; **test = the full 10,000-image set for every row**): centralised upper bound **0.9756**, FedAvg IID **0.9620**, and FedAvg under Dirichlet (α = 0.5) non-IID label skew **0.9653** (40 rounds × 2 local epochs).*
- Reported a clean negative result that reverses the synthetic story: **FedProx did not recover non-IID accuracy on real data** — its best configuration scored 0.9520 (μ = 0.01), below FedAvg at every μ screened — and FedAvgM and FedAdam also lost to plain FedAvg on validation and were never test-evaluated. More communication rounds, not the proximal term, were the lever that worked.*
- Quantified the privacy–utility trade-off with per-sample-clipped DP-SGD: **0.9054 at ε̂ ≈ 5.55** and **0.9083 at ε̂ ≈ 10.2** (epsilon-hat; δ = 1×10⁻⁵; full estimated frontier 0.7898 @ ε̂ ≈ 3.81 → 0.9218 @ ε̂ ≈ 15.31) — roughly 6 accuracy points at ε̂ ≈ 5.55 against the non-private federated best. Every ε̂ is the project's **simplified RDP estimate**, labelled as an estimate, never a formal guarantee.*
- Built the system from scratch in PyTorch (FedAvg/FedProx aggregation, per-sample-clipped DP-SGD with Gaussian noise, IID and Dirichlet partitioning with per-client label histograms) and recorded why the real numbers sit *above* the synthetic ones almost everywhere: MNIST-16 is simply an easier task than the synthetic problem — the old table's ordering survived, its absolute values did not. DP gains came from learning-rate tuning (0.4 → 2.0); tighter clipping (C = 0.5) hurt and was dropped.*

## 6. ResolveDesk AI — AI Customer Support SaaS (Product)

- Designed and shipped a working multi-tenant AI support product (Python stdlib + SQLite + NumPy, zero external APIs): per-business knowledge bases, an embeddable chat widget that answers with citations, and a confidence gate that creates a support ticket instead of guessing when retrieval confidence is low; tenant isolation verified by tests — 13/13 tests and a 10/10 end-to-end HTTP smoke test pass. The shipped product model was **not** retrained on benchmark data (the benchmark's 27-intent schema differs from the product's 6 intents).*
- Re-evaluated the triage classifier on a **real public benchmark — the Bitext customer-support dataset** (licence CDLA-Sharing-1.0; 26,872 rows, 27 intents, 11 categories) under a **deduplicated split as the headline protocol**: the final model reached **97.59% intent accuracy / 0.9748 macro F1** and **99.5% category accuracy / 0.995 macro F1** on the deduplicated test split.*
- Caught and quantified the leakage trap before headlining anything: on a naive random split the baseline reads 94.75%, but **13.79% of naive test rows appear verbatim in naive train** — that figure is reported as a leakage contrast only. The honest deduplicated baseline is **89.9% / 0.8608**, and ~4.9 points of the naive number was duplicate leakage.*
- Improved the classifier on validation only: deduplication itself unbalances the classes (421–997 unique utterances per intent), so inverse class weighting alone lifted validation macro F1 0.848 → 0.9547, with word bigrams + char 3–5-grams reaching the 0.9784 plateau; the baseline's collapsed `cancel_order` intent (F1 0.0) recovered to 0.9586, with `change_order` (0.9261) the weakest final intent. **Priority prediction has no real labels in Bitext and remains synthetic-only** (98.3% priority accuracy on the project's synthetic held-out set) — never a real-data claim.*
