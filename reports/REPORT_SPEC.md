# Thesis Report Spec — one report per project (Ashutosh Sahoo, 2026-11-05)
Deliverable per project: PDF (primary) + DOCX (editable), ~25-40 pages, in ~/workspace/advanced-ai-projects/reports/
Written so a learner can study the project end-to-end and an interviewer can verify depth. ALL numbers copied from that project's results.json only.

## Structure
1. Cover page: title, author (Ashutosh Sahoo, M.Tech AI, NIT Silchar), date, one-line result headline
2. Abstract (250 words) + Keywords
3. Table of contents
4. Ch 1 Introduction: problem, why it matters, objectives, contributions
5. Ch 2 Background & Theory: every core concept explained from first principles with formulas (e.g. LoRA low-rank update, DDPM forward/reverse, FedAvg aggregation, BM25, segmental F1) + SOTA literature context
6. Ch 3 System Design & Architecture: diagrams, data flow, module map
7. Ch 4 Implementation: EVERY file, feature and function explained — function-by-function walkthrough with key code snippets, design decisions and why
8. Ch 5 Dataset / Corpus: how built, statistics, splits, limitations (synthetic disclosed)
9. Ch 6 Experiments: setup, hyperparameters, sweeps, baselines, ablations — full protocol so results are reproducible
10. Ch 7 Results & Analysis: every table/chart from results.json, what each number means, why baselines lose, failure cases, error analysis
11. Ch 8 Discussion: limitations, threats to validity, production / scale-up path (Kaggle GPU, real datasets)
12. Ch 9 Conclusion & Future Work
13. Learning Guide: concept checklist, "explain it in an interview" Q&A (10+ questions with model answers), exercises to extend the project
14. How to Run: step-by-step commands
15. References
16. Appendix: full results.json, file listing

## Design standard (added 2026-11-05 — all report PDFs must follow this)
Plain-text PDFs are NOT acceptable. Every thesis report PDF is rendered with
`build_designed_pdf.py` (in this folder, reportlab Platypus + matplotlib):

- **Cover:** full-page deep navy (#0B1226), accent geometric shapes, big white title,
  subtitle, "Headline Results" panel (3–4 metrics from results.json), author block
  (Ashutosh Sahoo, M.Tech Artificial Intelligence, NIT Silchar, November 2026).
- **Per-project accent:** AgentForge #2B50C8 (Kriya blue) · ResolveDesk #4F46E5 (indigo) ·
  Sentinel-LLM #DC2626 (security red) · DenseHAR #7C3AED (violet) ·
  DiffusionForge #DB2777 (magenta) · FedGuard #059669 (emerald). All 6 configs already
  exist in build_designed_pdf.py — for the remaining 3 reports, fill in their headline
  metrics + a charts_for() branch from their results.json, then run the script.
- **Interior:** A4, running header (project left, current chapter right) + footer
  (author left, page number right), accent-underlined chapter headings, styled tables
  (accent header row, zebra rows), monospace code on light grey, tinted callouts,
  accent list markers, Noto Sans body ~10.5pt.
- **"Results at a Glance" page** right after the cover: metric tiles + accent-matched
  matplotlib chart(s) built ONLY from the project's results.json + a factual caption.
- **Contents page** after the glance page (chapter list from the md headings).
- **QA (mandatory):** pdftoppm the cover, glance, contents, a body page and a table
  page; read the PNGs; fix overflow/clipping/contrast before delivering.
- Keep the old plain render as `<slug>-report-plain.pdf.bak` when overwriting.
- The .md stays the content source of truth — the renderer never changes content
  or numbers; .docx companions stay as generated by the report writers.
